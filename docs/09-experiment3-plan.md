# 실험 3 계획: 데이터 다양화 + LoRA 설정 원복

## 배경 — 실험 2에서 발생한 문제

`docs/08-experiment2_training_log.md`에 정리했듯, 실험 2(4자리 heading 타깃)는
eval loss가 0.99까지 떨어졌음에도(실험 1: 4.09) 실제 생성 결과는 baseline보다도
나빴다(`docs/07-experiment2_finetuned_result.md`: Exact 0.40% vs baseline 2.61%).
GGUF 변환 전 병합 모델을 transformers로 직접 로드해 같은 프롬프트를 넣어봐도
`"6 6 6 6 ... 6"`처럼 숫자 "6"만 반복하는 완전한 mode collapse가 확인됐다 —
GGUF/양자화 문제가 아니라 학습 자체의 문제였다.

## 원인 분석

1. **데이터 편중**: `data/processed/train.jsonl`(1994건)의 `hs_code` 첫 자리가
   **100% "6"**이다. 원본 소스(`data/raw/products_real.csv`, 356건)가 61류/62류
   (의류) 품목만으로 구성돼 있기 때문이다(61류 177건, 62류 179건, 그 외 0건).
   4자리 타깃으로 바꾸면서 고유 클래스도 34개로 줄었다.
2. **LoRA 용량 확대**: 실험 2는 실험 1 대비 `lora_r 16→32`, `lora_alpha 32→64`로
   키우고, 학습 대상 모듈에 attention(q/k/v/o) 외에 **MLP 레이어(gate/up/down_proj)
   까지 추가**했다.
3. 위 두 요인이 겹치면서, 모델이 "그냥 6을 반복하면 loss가 잘 떨어진다"는 얕은
   지름길에 완전히 최적화된 것으로 추정된다. 데이터 편중 자체는 실험 1도
   동일했지만(같은 소스), 그때는 이 정도로 붕괴하지 않았다는 점에서 LoRA 용량
   확대가 붕괴를 유발한 주된 방아쇠였을 가능성이 크고, 데이터 편중은 그 지름길을
   "가능하게 만든" 조건으로 판단된다.

## 결정 사항

1. **데이터 다양화**: 61/62류(의류)에만 편중되지 않도록 다른 류의 품목 데이터를
   추가한다. 전체 97개 류를 다 다루는 것은 현재 데이터 수집 여력과 2B급 소형
   모델의 용량을 감안할 때 비현실적이라고 판단, 아래로 범위를 좁힌다.
   - 의류 인접류(63류 기타 섬유제품, 64류 신발) + 계열이 완전히 다른 류
     (84/85류 전자제품) 정도를 추가 후보로 우선 검토한다.
   - 목표는 "6으로 시작하지 않는" 데이터가 전체의 20~30% 이상을 차지하도록
     구성하는 것 — 특정 숫자 하나로의 지름길 학습을 원천 차단하는 최소 조건으로
     본다.
   - **미해결 과제**: 현재 `data/raw/`에는 61/62류 외 실사용 가능한 데이터가
     없다(`dummy_products.csv`는 16건뿐인 시드 데이터). 신규 데이터 확보 방법을
     별도로 정해야 한다.
2. **LoRA 설정 원복**: 실험 2에서 키운 용량을 실험 1 수준으로 되돌린다.
   - `lora_r`: 32 → 16, `lora_alpha`: 64 → 32
   - `target_modules`: MLP 레이어(gate/up/down_proj) 제외, attention
     (q/k/v/o_proj)만 유지
   - epoch 수는 실험 2와 실험 1 사이에서 재검토(데이터 규모가 늘어나므로 별도 결정)
