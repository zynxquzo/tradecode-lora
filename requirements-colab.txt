# src/finetune/train.py, merge_adapter_plain.py 전용 — GPU 환경(Colab T4, Kaggle 등)에서만 설치.
# 로컬 머신은 CUDA GPU가 없어 requirements.txt와 분리했다.
#
# unsloth는 더 이상 쓰지 않는다 — 실험 3에서 unsloth로 학습한 adapter가 unsloth
# 자체 로드/추론 경로에서는 정상 동작했지만, 병합 방식을 6가지 넘게 바꿔가며
# 테스트해도 unsloth 밖(순정 transformers, GGUF/llama.cpp)에서는 전부 동일한 증상으로
# 실패했다 - unsloth의 Gemma-2 계산 방식이 순정 구현과 근본적으로 달라서였다
# (docs/10-experiment3_investigation.md 7~9절 참고). 학습을 순정 transformers +
# peft(QLoRA) + trl로 바꿔서 학습·추론이 같은 계산 경로를 쓰게 만들었다.
#
# trl만 버전을 고정했다: train.py의 SFTConfig/SFTTrainer 호출부가 trl==0.24.0의
# 실제 파라미터명(max_length, processing_class, bf16 기본 동작)에 맞춰 작성돼 있어서,
# trl이 더 최신으로 알아서 올라가면 또 API가 바뀌어 깨질 수 있다. transformers/peft/
# accelerate/bitsandbytes는 pip가 trl==0.24.0과 호환되는 조합을 알아서 풀도록 버전을
# 고정하지 않았다.
# trl 버전을 올려야 하면: 1) 이 핀을 올리고 2) train.py 상단 주석의 API 노트와
# SFTConfig/SFTTrainer 호출부를 새 버전 시그니처에 맞춰 같이 수정할 것.
# peft(버전 미고정)가 병합 시 torchao 백엔드 dispatch 가능 여부를 체크하는데,
# Kaggle 기본 이미지의 torchao(0.10.0)가 peft가 요구하는 최소 버전(0.16.0)보다
# 낮으면 조용히 건너뛰지 않고 ImportError를 던진다(merge_adapter_plain.py 실행 시
# "Found an incompatible version of torchao" 에러). torchao를 실제로 쓰지 않는
# 병합 경로인데도 걸리는 순전한 버전 체크 문제라, torchao만 최신으로 올려 회피한다.
